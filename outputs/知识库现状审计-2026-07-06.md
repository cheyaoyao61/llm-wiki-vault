# 知识库现状审计（2026-07-06）

本报告记录第一次轻量 LLM Wiki 升级的审计范围、主要问题、实施动作和后续风险，便于以后判断治理规则为何存在。

## 审计范围

- 根目录规则：`AGENTS.md`、`CLAUDE.md`。
- 原始资料：`raw/` 下 1 个 DOCX 和 1 个 PDF。
- 结构化知识：`wiki/` 下原有 5 篇主题笔记和 `INDEX.md`。
- 输出目录：升级前为空。

## 升级前主要问题

1. 来源只标文件名，没有页码或段落定位。
2. SCOR 第12版、五流程、六流程和不同层级口径被混合使用。
3. 企业案例数字来自二手汇编，却被写成无条件确认的事实。
4. “目前、至今、现”等表述缺少资料时间。
5. 原始资料中的“灵峰/灵蜂”、人员变化等分歧没有记录。
6. 物流面积和设备公式过度简化，可能误导实际项目。
7. 缺少来源目录、生命周期、状态、模板和验证规则。

## 本次实施

- 保留 `raw/wiki/outputs` 三层结构。
- 创建升级前快照和 `raw/` SHA-256 基线。
- 将 `AGENTS.md` 扩展为 Codex 主协作规则，`CLAUDE.md` 作为 Claude 入口。
- 新增知识生命周期、来源目录和三类模板。
- 重建索引，增加状态、维护入口和待补领域。
- 治理全部 5 篇原有主题笔记，保留有价值内容并增加来源、时效、边界和分歧。
- 将 SCOR 当前版本核验到 ASCM SCOR DS 14.0。

## 保留风险

- 两份原始资料均缺少足够的正式出版信息，可信度暂定为 C。
- 华为案例尚缺官方或独立来源交叉验证。
- 部分 DOCX 内容只有章节级定位，尚未全部补齐段落号。
- 当前主题集中在供应链基础和华为案例，WMS、OMS、TMS、MDM、技术架构与项目复盘仍为空白。

## 后续建议

1. 新增原始资料时先登记来源，不直接生成大量 Wiki。
2. 优先补充官方 SCOR、物流工程教材和真实项目材料。
3. 企业案例引用时保留“据二手资料记载”的限定。
4. 用真实项目逐步建设业务能力、状态机、数据流和技术决策知识，而不是预先生成泛化文章。
