# 运输合单拆单与数量守恒

合单、拆单和部分配载本质上是需求数量在计划或运单之间的可追溯分配；可靠设计的核心不是单据名称，而是互斥口径、逐笔台账、幂等操作和可审计的释放规则。

**状态**：已核验  
**最后更新**：2026-07-07  
**复核触发条件**：数量口径、计量单位、取消规则、短少处理或分配层级变化

## 业务机制

- 合单：多个需求的部分或全部数量分配到同一计划或运单。
- 拆单：一个需求分批分配到多个计划或运单。
- 部分配载：一次分配只占用需求的一部分可分配数量。
- 撤销分配：按原分配明细释放尚未执行的数量，而不是清空需求的汇总配载量。

Oracle OTM 明确支持将订单的全部或部分数量释放用于运输规划，也支持同一订单生成多个 release；这验证了部分释放和分批规划机制。[外部核验:Oracle Order Releasing Process，2026-07-07访问](https://docs.oracle.com/en/cloud/saas/transportation/25c/otmol/planning/order_manager/create_order_release.htm)

## 数量守恒

先固定同一货品、计量单位、需求版本和统计时点，再使用互斥桶：

```text
原始需求量
= 未分配有效量
+ 已分配未执行量
+ 已执行确认量
+ 已终止量
+ 异常挂账量
```

这是设计约束，不是 Oracle 的原文公式。（分析）“已终止量”只用于保留原始需求审计口径；若业务把取消直接修改为新的有效需求量，则不能再把取消量与新需求量相加。异常挂账在责任和归属确认后，必须转入其他互斥桶，不能永久重复占用。

## 台账最小字段

每笔分配至少记录：来源需求及版本、目标计划或运单、货品或运载单元、分配数量和单位、操作类型、幂等键、前后数量、操作者或触发事件、时间及原分配引用。

汇总数量应由有效台账聚合或可重建快照得到。仅保存“当前已配载量”会使取消、并发覆盖、短少和异常补偿不可审计。[来源:SRC-003，候选知识2]

## 异常处理

- 取消：只释放未执行且允许撤销的原分配；已执行部分进入退运、拒收或差异流程。
- 短少：实际量与计划量的差额先进入异常挂账，明确责任后再关闭或补运。
- 重复请求：以业务幂等键返回原结果，不重复占量。
- 并发配载：服务端以版本号、条件更新或锁保证累计分配不超过可分配量。
- 单位换算：必须保存原单位、换算规则和舍入差异，禁止直接混加件、箱、托和重量。

## 人工配载的服务端硬约束

人工负责选择方案，不代表系统可以放弃完整性校验。提交配载时，服务端至少应按当前业务启用的规则检查以下类别：[来源:SRC-003，候选知识3]

| 约束类别 | 检查内容 | 失败处理 |
|---|---|---|
| 数量 | 剩余可分配量、最小拆分单位、重复占用 | 拒绝超配，返回冲突明细 |
| 重量与体积 | 车辆或装载单元的载重、容积及必要的轴荷约束 | 拒绝超限，不用警告代替拦截 |
| 车型与资源 | 车型、车长、温控或装卸能力是否满足任务要求 | 要求重新选择合格资源 |
| 时窗 | 取送货、运输计划及预约时窗是否可同时满足 | 标明冲突站点和时间范围 |
| 货物兼容 | 混装禁忌、温区、危险属性、污染或堆码约束 | 禁止不兼容货物共载 |
| 路线可达 | 站点顺序、道路或场站限制、车辆通行能力 | 拒绝不可执行路线 |
| 并发版本 | 需求余量、车辆能力和计划版本是否已被其他操作修改 | 终止本次提交并要求刷新 |

这是一份跨项目设计检查框架，不是法规意义上的完整约束集。（分析）危险品、冷链、超限运输和特定地区通行规则必须另行采用适用法规、合同和主数据配置；不能把本表当成固定清单。路线与逐站载量校验见 [[03-多点运输站点与运输段]]，预约冲突见 [[04-运输预约与场站协同]]。

## 适用边界

适用于允许分批运输或共享运力的业务。不适用于法规或合同明确要求整单独占、不可拆不可合的对象；即使不可拆分，也仍建议保留分配和撤销审计记录。

## 设计检查

1. 数量桶是否互斥且能在任意时点重算？
2. 合单与拆单是否共用一套分配明细，而非两套特例代码？
3. 撤销是否引用原记录，且禁止释放已执行量？
4. 数量、重量、体积、车型、时窗、货物兼容、路线可达和并发版本是否在服务端校验？
5. 人工操作是否仍可能绕过硬约束或只收到警告？
6. 短少、拒收、破损和超发分别落入哪个数量桶？
