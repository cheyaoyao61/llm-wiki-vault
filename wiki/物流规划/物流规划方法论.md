## 应用范围

SRC-001 将物流规划应用概括为四类：[来源:SRC-001，DOCX段落86-118]

1. 运作管理：设计流程、功能区和作业方式。
2. 资源配置：选择人员、设备类型、数量和自动化程度。
3. 设施建设：选址、建筑形态、库容、面积和内部布局。
4. 信息化建设：为 WMS 等系统提供流程、任务、指标和算法基础。

## 系统分析要素

| 要素 | 需要回答的问题 |
|---|---|
| 供应链业务策略 | 需求由预测、订单还是工程项目触发？ |
| 供应链流程 | 物流需求由哪个上下游活动触发？ |
| 组织 | 谁提供数据、决策和执行？ |
| 网络角色 | 当前节点在供应网络中的位置是什么？ |
| 物流环节 | 属于采购、生产、销售还是回收物流？ |
| 物流活动 | 卸货、理货、上架、拣选等动作如何衔接？ |
| 指标 | 用什么衡量服务、成本、效率和质量？ |
| 字段 | 系统需要记录哪些时间、地点、数量和状态？ |
| 数据分析 | 使用统计、计算、优化还是仿真？ |

## 九步问题分析法

1. 明确问题和发起方。
2. 定义范围、组织和边界。
3. 确定结果指标及评价标准。
4. 明确指标公式、变量和口径。
5. 将变量映射到具体物流活动。
6. 获取数据并检查质量。
7. 设计方案并比较指标变化。
8. 与相关部门验证可执行性。
9. 建立监控和持续改进机制。

[来源:SRC-001，DOCX段落67-85]

这套方法适合问题拆解，但“迭代至最优”通常只能得到约束和假设下的较优方案，不能默认存在或已经找到全局最优。（分析）

## 运输履约设计与复盘检查

运输场景不能只画“订单→需求→计划→运单”的对象箭头。每个关键场景至少回答：触发条件、参与角色、输入、对象变化、数量分配、地点与路线、时间与预约、资源分派、状态与异常。[来源:SRC-003，候选知识7]

复盘时应使用带数量的案例验证合单、拆单、部分履约、取消和短少，并记录适用条件、不适用条件及简化边界。该九项清单来自一次项目复盘实践，具有方法参考价值，但尚不是行业标准。（分析）

具体机制见 [[01-运输履约对象模型]]、[[02-运输合单拆单与数量守恒]]、[[03-多点运输站点与运输段]]、[[04-运输预约与场站协同]] 和 [[05-运输履约状态与变更传播]]。

## 物流中心作业

典型流程可以抽象为：[来源:SRC-001，物流中心相关章节，定位待补]

```text
预约/到货 → 卸货 → 验收/理货 → 上架/暂存
→ 补货/拣选 → 复核/包装/加工 → 集货 → 装车/发运
```

实际项目必须补充质检、异常品、退货、盘点、波次、越库和安全作业等分支。

## 资源分类

- 存储：地堆、货架、高位库、自动化立体库。
- 搬运：托盘车、叉车、输送线、AGV/AMR。
- 识别与分拣：条码、RFID、视觉和自动分拣。
- 运输：车辆、装载单元和调度资源。
- 人员：收货、上架、拣选、复核、设备与现场管理岗位。

## 数量与面积估算

### 仓储面积

原笔记曾简化为“库存量 × 单位货物占地 + 通道面积 + 功能区面积”。该表达缺少堆码层数、存储方式、库位利用率、峰值库存、消防和建筑约束，只能作为变量提示。

更合理的估算结构是：

```text
存储需求 → 托盘/料箱/库位数量
库位数量 ÷ 可用高度与存储密度 → 存储区面积
存储区面积 + 作业区 + 暂存区 + 通道 + 辅助区 → 建筑需求
```

每一步都必须明确峰值口径和利用率，最终还需建筑、消防、安全及设备专业校核。（分析）

### 设备数量

原笔记写作“日处理量 ÷ 单台设备效率 × 利用系数”。如果“利用系数”表示小于 1 的可用率，这个方向会低估设备数量。

概念公式应写为：

```text
设备数量 = 峰值周期工作量 ÷（单台额定效率 × 可用工作时间 × 综合利用率）
```

结果向上取整，并校验瓶颈、故障冗余、充电、换班和任务不均衡。该公式仍需用真实作业数据或仿真验证。（分析）

### 波动与弹性

资源配置不能只看日均值，应至少分析峰值周期、季节性、促销、到货集中度、订单结构和服务时限。安全库存解决的是不确定性缓冲，不能替代产能和流程设计。

## 指标设计

| 层级 | 典型指标 | 常见陷阱 |
|---|---|---|
| 网络 | 覆盖、时效、运输成本、韧性 | 只降成本而忽略服务和风险 |
| 节点 | 库容、吞吐、准确率、单位成本 | 平均值掩盖峰值瓶颈 |
| 作业 | 人效、设备效率、等待、差错 | 指标口径不一致或局部优化 |

指标必须记录定义、单位、时间粒度、过滤条件和责任系统，否则无法跨期比较。（分析）

## 跨部门协同

物流规划通常需要生产、销售、采购、工程、财务和 IT 共同参与。[来源:SRC-001，企业物流规划相关章节，定位待补] 协同的核心不是开会，而是明确输入数据、约束、决策权和验收指标。
