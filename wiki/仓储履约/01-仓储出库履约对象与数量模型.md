# 仓储出库履约对象与数量模型

仓储出库应把需求、库存预占、仓内作业、装运交接和库存出账分开建模；它们可以来自同一订单链路，但不是同一个事实，也不应共用一个布尔状态来表达全部进度。

**状态**：已核验  
**最后更新**：2026-07-08  
**复核触发条件**：补充新的 WMS 项目验证；SAP EWM、Oracle WMS 等主流产品对象模型发生明显变化；出现需要区分财务出账与仓内移动的新资料

## 核心分层

| 层次   | 表达的问题          | 典型事实                |
| ---- | -------------- | ------------------- |
| 出库需求 | 要从仓库交付什么、给谁、多少 | 出库请求、订单行、仓储请求       |
| 库存预占 | 哪些库存被承诺给本次需求   | 分配量、释放量、保留量         |
| 仓内作业 | 人或设备实际搬运什么     | 拣货、复核、包装、移库、装车前暂存   |
| 装运交接 | 货物是否交给运输或场站环节  | 装车、发运、交接确认          |
| 库存出账 | 库存所有权或账面数量是否减少 | Goods Issue、库存扣减、冲销 |

SAP EWM 将仓储请求用于处理特定产品数量，仓储任务用于执行货物移动；拣货、装载和 Goods Issue 是不同过程，Goods Issue 过账会减少库存。[来源:SAP Help，Warehouse Request，访问日期2026-07-08](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT/57574d15fa1d414792d74047b66c3e41/64c8cb53ad377114e10000000a174cb4.html) [来源:SAP Help，Goods Issue，访问日期2026-07-08](https://help.sap.com/docs/SAP_EXTENDED_WAREHOUSE_MANAGEMENT/3d97bec9bf1649099384bb8167df3cf2/c4c8cb53ad377114e10000000a174cb4.html)

## 数量台账

部分分配、部分拣货、部分装车和部分出账都应使用数量台账，而不是只用“完成/未完成”。台账至少区分以下互斥数量桶：

- 需求数量：业务上仍要求履约的数量。
- 已预占数量：已经锁定或承诺的可用库存。
- 已释放数量：曾经预占但被释放回可用库存的数量。
- 作业中数量：已生成作业但尚未形成最终交接或出账。
- 已装运数量：已完成装运交接的数量。
- 已出账数量：已经扣减库存账的数量。
- 终止数量：经授权不再继续履约的数量。

取消量、短拣量和终止量不能混写。取消量可能是原始需求变更，短拣量是执行差异，终止量是差异处置后的业务结果。（分析）

## 设计建议

- 先定义每个对象拥有的数量事实，再设计状态；状态只应是事实聚合后的读模型。
- 多入口出账时，不必强制所有入口调用同一个物理接口，但必须共享同一出账规则、幂等边界和审计口径。
- 一单多车、分批装运、部分分配和作业中改量都应按数量行或数量事件处理，不能只靠订单头状态推断。
