# 知识库维护规则

本规则定义原始资料和外部知识候选从进入审核到形成、复核和淘汰正式知识的完整生命周期，目标是在不增加重型基础设施的前提下，使知识可追溯、可更新、可解释。

**状态**：已核验  
**最后更新**：2026-07-06  
**复核触发条件**：目录结构、来源格式或维护流程发生变化

## 知识生命周期

```text
原始资料进入 raw/，或外部项目生成脱敏候选
  → 来源与证据登记
  → 脱敏和通用性审核
  → 识别可复用主题
  → 新建或更新 Wiki
  → 论断级来源标注
  → 时效与冲突检查
  → 更新 INDEX
  → 定期或事件触发复核
```

### 1. 原始资料进入

- `raw/` 保存原件，永不直接编辑。
- 文件重名、版本不明或来源不清时，先登记问题，不自行改名。
- 新资料不必“一份资料对应一篇笔记”；应按稳定主题整合。

### 2. 来源登记

- 在 [[来源目录]] 分配唯一编号，例如 `SRC-001`。
- 记录文件名、资料时间、来源类型、可信度和已知限制。
- 无作者、无版本、无出版信息的资料不得评为 A 或 B。

### 3. 提炼与引用

- 稳定概念、方法和架构进入 `wiki/`。
- 一次性回答、审计和阶段报告进入 `outputs/`。
- 关键论断在句末就近引用，不只在文末罗列文件名。
- 原文事实、外部核验和分析推断必须能被读者区分。

### 4. 外部项目与专题候选

- 来源项目保存项目专属事实、客户约束、代码证据和完整过程记录。
- 个人知识库只接收已脱敏、经过抽象且可能跨项目复用的候选。
- 候选不是正式知识；证据不足、适用范围不清或无法证明通用性时继续保留候选状态。
- 敏感信息、账号、内部地址、源代码和客户隐私不得进入个人知识库。
- 读取外部候选前，先读取来源项目的 `AGENTS.md` 和候选说明；知识库不反向修改来源项目事实。
- 无法访问关键证据时，不得将候选标记为已核验事实。

候选审核依次检查：来源与证据、脱敏、跨项目复用性、事实与推断区分、现有 Wiki 去重、冲突与适用范围、外部时效核验，最后决定新建、合并、补充、保留候选或拒绝晋升。

知识落点遵循内容性质：稳定知识进入 `wiki/`；成熟且重复使用的设计模式和操作方法，确有内容时再分别建立 `patterns/`、`playbooks/`；一次性分析进入 `outputs/`。不得机械创建空目录。

## 引用规范

```markdown
SCOR 最早由 SCC 于 1996 年提出。[来源:SRC-002，PDF第8页]

该公式仍缺少峰值系数和利用率口径，当前只能用于概念估算。（分析，待项目数据验证）
```

定位优先级：页码或章节 > DOCX 段落号 > 文件级定位。扫描件页码优先使用 PDF 文件页码，并在必要时补充印刷页码。

## 时效管理

不要求机械地按固定周期刷新全部笔记，优先使用事件触发：

- 标准、法规或软件发布新版本。
- 企业组织、产品、经营数字或案例状态变化。
- 新项目证据推翻旧经验。
- 新来源与现有结论发生冲突。
- 正文出现“当前、目前、至今、最新”等词语。

稳定概念可低频复核；版本、法规、组织和经营数据应在引用前复核。无法复核时，将状态改为“待复核”，并保留历史表述的资料时间。

## 冲突处理

1. 分别记录各来源观点和精确定位。
2. 检查是否属于不同时间、版本、范围或指标口径。
3. 证据足够时给出带理由的判断。
4. 证据不足时保留分歧，并列出需要补充的证据。

禁止通过删除其中一方、模糊措辞或擅自统一口径来隐藏冲突。
